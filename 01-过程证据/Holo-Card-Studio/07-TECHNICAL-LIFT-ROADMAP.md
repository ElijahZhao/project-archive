> 两条主线：① 物理仿真全息 shader（计算光学） ② AI 素材质检流水线（视觉 QA）

## 主线 ① 物理仿真全息 shader —— From Art Approx to Physical Optics

### 1. 问题定义

当前"全息效果"是**美术近似**：详情页 GLSL 用彩虹渐变贴图按视角扫过卡面，Blender 用近似节点模拟。视觉达标，但在技术上属于"贴图作弊"——无法讲深，也无法与真实镭射卡的光学原理对应。

目标：把全息效果升级为**真实镭射卡的物理仿真**——卡面微米级周期光栅对白光的波长分解，彩虹随视角**物理正确地移动**（不是贴图扫过）。

### 2. 光学原理（真实镭射卡的物理）

真实镭射卡表面压印周期性微结构（光栅/全息母版），白光入射后：

- **薄膜干涉（thin-film interference）**：光线在半透明膜（厚度 d、折射率 n）上下表面反射，相位差 δ = 2·n·d·cosθ 使不同波长的反射率周期性变化 → 产生"油彩渐变"。
- **光栅衍射（grating diffraction）**：周期光栅方程 m·λ = d·(sinθi ± sinθm)，不同波长 λ 在不同出射角相长干涉 → 观察者看到随视角变化的彩虹（1 阶/2 阶）。
- **微表面散射**：表面粗糙度（GGX 分布）决定彩虹的锐利程度与各向异性。

### 3. 仿真模型选择（三档）

| 档位 | 模型 | 效果 | 成本 | 推荐 |
|---|---|---|---|---|
| L1 | 薄膜干涉（色散核心） | 油彩渐变、Newton 环物理 | 低（单波长循环 ×3） | ✅ 必做 |
| L2 | 微表面 GGX + 光栅方位角依赖 | 方向性彩虹、各向异性 | 中（多波长采样 3-8） | ✅ 必做 |
| L3 | Fraunhofer 全衍射（光栅方程逐阶） | 最物理（可验证 1/2 阶） | 高 | Blender 离线验证用 |

**落地组合：L1 + L2**（薄膜干涉给色散基底、GGX+光栅方位给方向性彩虹），L3 只做离线对照验证。

### 4. 双实现架构（延续"同一套数学两个引擎"叙事）

- **统一光学模型文档** `docs/GRAPHICS/HOLO-OPTICS.md`：公式推导（薄膜相位差、光栅方程、GGX 微表面）+ 伪代码 + 参数定义，两个引擎共用。
- **Blender（Cycles）**：OSL Shader / Node Group 实现 → hero 渲染 + GLB 材质。
- **详情页 GLSL**：替换现有 fragment shader 的 foil 模块 → 实时物理彩虹。
- **输入参数一致**，写入 `card-config.json`：
  ```json
  {
    "foil": { "thickness_nm": 320, "ior": 1.5, "grating_period_um": 1.8,
              "grating_azimuth_deg": 30, "roughness": 0.18, "wavelength_samples": 6 }
  }
  ```
  每卡一组参数 = 该卡**独有的光学指纹**，与"每卡独特工艺名"叙事打通（工艺名可以升级为"光学配方"）。

### 5. 验证方案（可审计）

1. **同视角对照**：同一视角下 Blender 渲染 vs GLSL 实时输出 → 计算色差 ΔE（CIELAB），目标 ΔE < 8（肉眼可忽略）。
2. **旋转视频**：录制彩虹随视角移动的对比视频（仿真 vs 真实镭射卡）。
3. **参数扰动测试**：改变 thickness/azimuth → 彩虹位置/方向按物理公式变化（验证不是贴图）。

### 6. 风险与对策

| 风险 | 对策 |
|---|---|
| GLSL 波长采样成本 | 6 波长 × 低分辨率预计算 LUT（膜厚→反射率） |
| Blender OSL 兼容性 | Cycles CPU 模式验证，fallback 为 Node Group |
| 与现有卡片视觉断裂 | 试点卡先做 A/B，默认参数对齐现有观感 |

### 7. 产出（含金量载体）

- 技术笔记《From Art Approximation to Physical Optics: A Holographic Foil Shader》**中英双语**（公式、双实现对照、ΔE 验证数据）
- 复现脚本：Blender OSL + GLSL + 对比渲染脚本
- 试点卡：王亥（已有四层资产，不动素材，只换材质/着色）

## 主线 ② AI 素材质检流水线 —— Automated Visual QA Gate

### 1. 问题定义

现在素材质量靠人工五道把关（四肢完整 / 对比度 / 透明通道 / 主体占比 / 正视角）。人工把关不可复现、不可扩展（78+ 张卡后越来越累），也讲不出"AI 交叉"的技术故事。

目标：把五道把关**自动化**，作为 pipeline 硬门禁（不过关自动打回重生成提示），同时保留人工验收（AI 管不了审美）。

### 2. 五道门 → 自动检测器映射

| 门 | 检测器 | 原理 |
|---|---|---|
| G1 主体完整性 | MediaPipe Pose（人物）/ rembg u2net 掩膜连通性（非人物） | 关键点计数（双上肢/双下肢齐全）；掩膜无断裂碎片 |
| G2 清晰度/对比度 | Laplacian 方差 + 灰度直方图跨度 | 模糊检测；对比度阈值 |
| G3 透明通道质量 | alpha 通道统计 | 残边占比、半透明噪点、边缘硬度 |
| G4 主体占比/构图 | 显著性掩膜 bbox | 占比 ∈ [0.35, 0.75]，居中偏差上限 |
| G5 正视角/遮挡 | 掩膜质心 + 边缘对称性（可选） | 侧面/遮挡预警 |

### 3. 实现架构

```
generator/qa/
├── quality_gate.py        # 主入口：四层 PNG → {pass, scores, issues} JSON
├── detectors/
│   ├── completeness.py    # G1 姿态/掩膜
│   ├── sharpness.py       # G2
│   ├── alpha_quality.py   # G3
│   └── composition.py     # G4/G5
└── config/qa_thresholds.json   # 阈值可配置，per-series 可调
```

- 依赖：MediaPipe（CPU，零 API）+ OpenCV + rembg（u2net 已有缓存）
- **零 API 成本**：全部本地推理，符合"不调 ARK API"铁律
- 接入点：
  - `run_pipeline` 前置门禁（不过关 → 提示重生成；`--force` 手动放行）
  - Actions `gallery-check` 扩展：对**新增卡**强制质检，历史卡只跑轻量门（G2/G3）
  - 输出存 `qa_reports/<card_id>.json` 供审计

### 4. 关键设计决策

1. **per-card 阈值白名单**：梗图卡（哈兰德"哈哈哈兰德"）主体"不完整"是故意的 → `qa_overrides` 允许豁免指定门。正经卡与梗卡阈值分开。
2. **不取代人工验收**：AI 门禁 = 第一道（物理/结构），人工 = 第二道（审美/语义）。
3. **可复现**：检测器参数 + 阈值全部入库，QA 报告随卡归档（策展时间线可展示）。
4. **CI 时长可控**：CPU 推理 3-8s/卡，增量检测不会拖慢 CI。

### 5. 验收标准

- 对 5 张历史卡回放：人工判定与自动门禁一致率 ≥ 90%
- 故意破坏素材（截掉手臂/加噪/半透明边）→ 100% 被 G1/G2/G3 拦下
- CI 全绿（新增卡强制门禁通过后才能合入）

### 6. 产出（含金量载体）

- 技术笔记《Automated Visual QA for Generative Pipelines》**中英双语**（检测器选择、阈值校准方法、误报管理）
- 复现脚本 + 阈值校准数据集（历史卡 5 张 + 破坏样本）
- 面试叙事："生成管线里的视觉质量工程"——AI 应用方向的真实落地
