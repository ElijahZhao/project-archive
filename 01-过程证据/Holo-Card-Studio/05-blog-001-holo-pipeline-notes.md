# 把一句话变成一张会闪的 3D 卡：一个 AIGC 全链路管线的工程笔记

> HoloLab Studio 开发实录 · 作品集技术博客 #001
> 关键词：图像生成 · 抠图 · 程序化建模 · GLSL · 静态部署

---

## 0. 我想做的东西

一句"给我做一张水墨风锦鲤闪卡，编号 No.001"，最后要变成一个**别人能在浏览器
里拖着转、翻面、看镭射流动**的 3D 全息卡，而且这张卡要能放进一个**任何人打开
链接就能玩**的在线展厅。

这个目标拆开是三件事：

1. **素材**：卡面需要四层——透明底主体、背景环境、白底黑线稿、文字；
2. **3D 化**：把四层图叠成带视差和镭射的 3D 场景，导出成网页可加载的 GLB；
3. **实时渲染**：浏览器里用 WebGL 逐帧重建视差与镭射效果，并打包成在线展厅。

## 1. 第一个决策：四层分而治之，不指望一个模型包办

一开始最容易犯的错是"让图像模型直接出一张整图"。但整图做不了视差——主体和
背景必须**分别移动**。所以第一步就是把任务拆成四层，每层选最合适的工具：

| 层 | 谁来做 | 为什么 |
|---|---|---|
| 主体（透明底） | 豆包 Seedream 生成 → rembg 抠图 | 生成模型不输出透明 PNG |
| 背景（环境空镜） | Seedream 单独生成 | 必须独立成层才能视差 |
| 线稿（白底黑线） | OpenCV 从透明主体提取 | AI 重画无法像素级对齐主体 |
| 文字 | 字体渲染 | 生成模型画中文字形不可靠 |

这个"分而治之"的思路贯穿了整个项目：**不迷信单一模型，让每层用最可靠的工具，
每层都有校验和兜底。**

## 2. 踩坑实录（真实的调试过程比结果更值钱）

### 坑 1：rembg 默认模型有 1GB，CPU 推理直接内存告急

rembg 新版默认用 bria-rmbg-2.0（1GB），在沙箱里对 1920×2880 的图推理直接
静默失败。换成 `u2net`（176MB）并把输入降采样到 1/2 推理再放大回去，19 秒完成。
结论：**大模型不一定更好，要适配你的运行环境。**

### 坑 2：`cv2.dilate` 把细黑线全抹白了

生成线稿时想"加粗黑线"，直觉用了膨胀（dilate）——膨胀取邻域**最大值**，黑色
（0）在 3×3 核里被白色（255）覆盖，1px 的黑线全被抹掉，产出一张纯白图。加粗
黑色线条应该用**腐蚀**（erode）。这个 bug 让线稿校验（要求存在深色像素）直接
失败，但也让我把 OpenCV 形态学操作彻底搞懂了。

### 坑 3：importmap 的三级路径地狱

展厅为了省体积把 three.js 抽成共享 vendor，每张卡的 importmap 要改成相对路径。
第一版少了 `build/` 一层，`three.module.js` 404；第二版少了 `examples/` 一层，
`jsm/` 下所有 addons 404。排查方式是看静态服务器的访问日志——**比浏览器控制台
更直接**。最后固定为 `../../vendor/three/build/three.module.js` + `.../examples/jsm/`。

### 坑 4：下载源被 403

Blender 便携版官方源对沙箱环境返回 403。换成清华镜像手动下载、SHA-256 校验后
放入 `tools/`，流水线检测到即复用。作品集里值得记一笔：**生产环境要有多源意识**。

### 坑 5：API 瞬时 403

豆包图像接口偶发 403（限流/瞬时），加了重试（指数退避）和断点续跑（已生成的
层直接复用，`--force-ai` 才重新生成）。断点续跑还意外成了好用的调试功能。

## 3. 架构：层与层之间用标准产物解耦

```
一句话/照片
   │  ai_generate.py
   ▼  四层 PNG（assets/）
   │  run_pipeline.py
   ▼  card.blend + renders/hero.png + web/（GLB + Three.js 查看器）
   │  publish_card.py
   ▼  gallery/cards/<id>/ + cards.json（JSON 清单，无数据库）
   │  git push
   ▼  GitHub Pages 在线展厅
```

每层之间只通过磁盘上的标准产物通信，任何一层都能独立替换。比如想换图像模型，
只改 `ai_generate.py`；想换查看器，只动 web 模板。

## 4. 一件小事：为什么展厅零后端也能"在线"

很多"公开可玩"的需求默认要服务器+数据库。但这里卡片的**生成发生在本地**，
线上只需要展示静态资产，所以：

- 卡片清单 = `cards.json`（JSON 文件，不是数据库）；
- 查看器 = 纯前端 Three.js；
- 托管 = GitHub Pages（免费、静态、全球可访问）。

**想清楚"什么是用户可交互的状态"**，很多场景根本不需要后端——这是这个项目
给我最实际的一课。

## 5. 反思与下一步

做得好的：分层解耦、可复现（prompt、参数、中间产物都在磁盘）、诚实记录
tradeoff（主体与背景分两次生成，构图一致性靠"背景留白+视差遮挡"缓解）。

待改进：网页素材 1920×2880 原图太大（~14MB/卡），需要压缩管线；双图光栅
（lenticular）模式还没接入；展厅自动分类没做。

下一步：把素材压缩做掉、接入光栅模式、多生成几张不同风格的卡把展厅填起来。
