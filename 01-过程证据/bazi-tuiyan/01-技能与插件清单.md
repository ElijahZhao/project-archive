## 二、必用技能——品质底线

### 2.1 test-driven-development

| 项目 | 说明 |
|------|------|
| **技能名称** | test-driven-development |
| **项目用途** | 排盘引擎 29 条规则全部先写测试后写实现；用 11 个命例（5 个验证命例 + 6 个古籍经典命例）做回归测试 |
| **对应大纲章节** | 第八节·必用技能；第九节 9.1 排盘正确性验收 |
| **使用阶段** | 排盘引擎开发（第一阶段） |
| **关键产出** | 排盘引擎单元测试套件，覆盖立春界年柱、夜子时、真太阳时校正、夏令时还原、大运顺逆、起运岁数、胎元/命宫/身宫、神煞起法等全部 29 条规则 |
| **使用要点** | 每条规则先写验收测试用例（含预期输出），再写实现代码直到测试通过；古籍命例作为端到端回归测试 |

### 2.2 frontend-design + frontend-skill

| 项目 | 说明 |
|------|------|
| **技能名称** | frontend-design + frontend-skill |
| **项目用途** | UI 主视觉设计：现代东方配色体系、干支字体层级、命盘卡片组件、四柱表/大运表布局 |
| **对应大纲章节** | 第八节·必用技能；第六节页面与功能 |
| **使用阶段** | 前端开发（第二阶段） |
| **关键产出** | 首页/排盘页输入组件、命盘展示页四柱主表区/辅助宫位区/大运流运区/关系分析区/可视化图表区的完整 UI |
| **使用要点** | frontend-design 负责整体视觉方向（现代东方美学，避免 generic AI 风格）；frontend-skill 负责具体页面实现（排版、间距、响应式） |

### 2.3 Dashboard Page

| 项目 | 说明 |
|------|------|
| **技能名称** | Dashboard Page |
| **项目用途** | 命盘展示页的四类 ECharts 可视化图表：五行能量环形/雷达图、大运时间线、五行旺相休囚死图、十二长生图 |
| **对应大纲章节** | 第八节·必用技能；第四节 4.5 可视化图表 |
| **使用阶段** | 前端开发（第二阶段） |
| **关键产出** | 四个 ECharts 图表组件，支持时间控制、数据快照、来源弹窗 |
| **使用要点** | 五行能量图用环形图展示五行分布比例；大运时间线用轴图展示十年趋势；旺相休囚死用热力矩阵；十二长生用状态流程图 |

### 2.4 gsap

| 项目 | 说明 |
|------|------|
| **技能名称** | gsap |
| **项目用途** | 命盘展示页动画：四柱干支依次浮现、五行环充能动画、大运轴滚动效果、命盘展开过渡 |
| **对应大纲章节** | 第八节·必用技能；第七节技术栈（Framer Motion 主 + GSAP 复杂序列） |
| **使用阶段** | 前端开发（第二阶段） |
| **关键产出** | 四柱浮现 timeline、五行环充能动画、大运轴滚动动画 |
| **使用要点** | GSAP 处理复杂动画序列（多元素时序编排）；Framer Motion 处理简单交互动画（hover、tab 切换）；两者配合使用 |

### 2.5 writing-plans

| 项目 | 说明 |
|------|------|
| **技能名称** | writing-plans |
| **项目用途** | 进入代码实现前，将项目大纲拆解为步骤化实施计划，明确每一步的范围、依赖、验收标准 |
| **对应大纲章节** | 第八节·必用技能 |
| **使用阶段** | 规划阶段（排盘引擎开发前、前端开发前各一次） |
| **关键产出** | 排盘引擎实施计划、前端实施计划 |
| **使用要点** | 计划应按排盘引擎 → 前端展示 → 解读模块 → 部署的顺序拆分；每步标注依赖关系和验收标准 |

### 2.6 security-best-practices

| 项目 | 说明 |
|------|------|
| **技能名称** | security-best-practices |
| **项目用途** | LLM API 安全：API key 只存后端环境变量绝不下发前端；`/api/interpret` 端点输入过滤与 prompt 注入防护；Rate limiting |
| **对应大纲章节** | 第八节·必用技能；第五节 5.2 LLM 润色模块 |
| **使用阶段** | 后端 API 开发（LLM 集成阶段） |
| **关键产出** | 安全的 `/api/interpret` API Route 实现，含输入校验、prompt 注入防护、key 隔离 |
| **使用要点** | TypeScript/Next.js 场景；重点审查 API Route 层和前端→后端数据流 |

### 2.7 executing-plans

| 项目 | 说明 |
|------|------|
| **技能名称** | executing-plans |
| **项目用途** | 按 writing-plans 产出的实施计划逐步执行，每个检查点暂停确认，确保不偏离计划 |
| **对应大纲章节** | 隐含于第八节 writing-plans 之后 |
| **使用阶段** | 实施阶段（全程） |
| **关键产出** | 按计划逐步完成的代码实现，每步有 review checkpoint |
| **使用要点** | 与 writing-plans 配合：先 plan 后 execute；每完成一个里程碑暂停确认 |

### 2.8 shadcn

### 5.4 GenerateImage（内置工具，可选）

| **工具名称** | GenerateImage（系统内置工具，非技能） |

### 6.2 research-guide（按需）

| 项目 | 说明 |
|------|------|
| **技能名称** | research-guide |
| **项目用途** | 如开发过程中发现某条排盘规则需要补充权威来源，或需要验证某个古籍原文，用此技能进行结构化调研 |

| **项目用途** | 从网页提取干净的 Markdown 内容，用于核查古籍原文页面、提取天文数据等 |
| **对应大纲章节** | 参考来源文件维护 |
| **使用阶段** | 按需——通常与 research-guide 配合使用：① research-guide 发现线索后用 defuddle 抓取目标网页原文；② 开发过程中需核查某条古籍原文时直接抓取（如核对《三命通会》某卷某段原文）；③ 验证神煞口诀时抓取命理资料页面做交叉验证 |
| **使用要点** | 替代 WebFetch，输出更干净；用于古籍数字化平台（国学大师、古诗文网、识典古籍、书格等）的内容提取；抓取结果经核查后更新到参考来源文件第六节古籍原文引录 |

### 6.4 integrated_code_mode（MCP 工具，推荐）

| 项目 | 说明 |
|------|------|
| **工具名称** | integrated_code_mode（MCP 服务器，提供 `Exec` 工具） |
| **项目用途** | 在隔离的 JavaScript 运行时中执行代码，用于排盘引擎算法快速验证、命例批量测试、多工具并行编排 |
| **对应大纲章节** | 第二节核心架构与数据流；第九节验收清单 |
| **使用阶段** | 排盘引擎开发（第一阶段）+ 测试验证阶段 |
| **关键产出** | 排盘算法验证脚本输出、命例回归测试批量运行结果 |
| **使用要点** | 通过 `Exec` 工具运行 JS 代码，可在代码内调用 `await tools.<tool_name>(args)` 编排其他工具；适合批量计算（如一次验证 11 个命例的四柱结果）、天文算法精度测试、纳音太玄数公式批量验证等场景；注意运行时不提供直接的文件系统/网络/进程 API，需通过暴露的工具间接访问 |
