# 从上游 fork 到独立作品：HoloLab Studio 是怎么长出来的

## 起点：我借了一副骨架

项目最开始不是从零写的。我 fork 了 [EverettFish/holo-card-studio](https://github.com/EverettFish/holo-card-studio)，MIT 协议，作者做了一套很有意思的东西：一张 3D 全息卡 = 四层 AI 生成图 + Blender 合成 GLB + 前端 Three.js 实时渲染。卡片能转、有视差、有全息感。

当时我判断这骨架值得借，理由很朴素：

- 全息卡的渲染路径（Blender → GLB → WebGL）是最费时的部分，从头做要折腾很久；
- 上游把这条路走通了，我接手时它已经能出卡；
- 我想做的不是一个渲染 demo，而是"别人也能玩"的产品。

## 我加了什么

借骨架不等于抄作业。对照上游，我主要做了这些：

| 层面 | 上游状态 | 我做的 |
|---|---|---|
| 入口 | 只有仓库脚本，得本地跑 | 网页版 Create Studio：一句话 → 自动扩写设计 → 提交 |
| 展示 | 单页卡片查看 | 展厅（画廊）+ 详情页 + 策展时间线 + 自动导览 |
| 投稿 | 无 | GitHub Issue 公开投稿流程，审核后永久入厅 |
| 语言 | 英文单语 | 中英双语 UI，卡片内容按题材用 8 种语言 |
| 隐私 | 无 | 隐藏解锁：密码卡未解锁不可见（比如朋友的马） |
| 质量 | 无硬约束 | 五道质量门禁 + 28 项 CI 测试 |
| 规模 | 几张示例卡 | 77 张卡，11 个系列 |

## 哪些是上游的，哪些是我的

写这段是因为有人会问。诚实拆一下：

- **属于上游的**：四层图 → Blender → GLB → Three.js 这条渲染主路径，初始目录结构，MIT 授权。
- **属于我的**：产品形态（创作入口、公开投稿、画廊交互）、大部分 UI 与动效、i18n 系统、CI 测试与质量门禁、性能压缩优化、策展与导览、以及全部 77 张卡的选题与制作流程。

我改过的部分远多于保留的部分，但我不装作没借过。README 里专门写了 Upstream & Evolution 一节，把传承关系讲清楚——这是对上游作者的尊重，也是作品可信度的一部分。

## 一个判断

全息卡的技术本身不难，难的是让一个陌生人愿意输入一句话、等几分钟、然后把成果留在展厅里。所以这个项目后来大部分精力花在"体验"和"流程"上，渲染只是地基。

技术起点是别人的，作品是自己的。这条线我一直分得比较清。
