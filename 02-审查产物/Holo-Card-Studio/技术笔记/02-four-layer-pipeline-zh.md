# 一张卡是怎么造出来的：四层管线设计

## 为什么是四层，不是一张图

一张卡最终是一个 GLB，在浏览器里用 Three.js 实时渲染，能旋转、有视差。但 GLB 不是直接生成的——它是 Blender 把四张 PNG 合成出来的：

1. **主体层**：人物/物体，居中，占画面大部分
2. **背景层**：环境，负责纵深和氛围
3. **线稿层**：沿主体轮廓的发光描边
4. **文字层**：标题、副标题、系列编号、稀有度

分层的理由是：WebGL 里每层单独放一个平面、错开一点深度，转动时才有真正的视差和全息感。单张平面图做不到这个效果——最多做个假位移。

文字层单独一层还有个好处：换语言不用重画主体。孟加拉语的雷伊卡、丹麦语的马卡、德语罗伊斯卡，都是只换文字层，主体层复用。

## 生成顺序和幂等

管线大致是：

```
一句话 → AI 扩写成设计稿 → 四层逐张生图 → 抠图（背景分离）
→ 文字层排版 → Blender 合成 GLB → 压缩 → 发布到 gallery
```

每一步都要求幂等：重跑一遍不能把状态跑坏。这点是用踩坑换来的。

## 踩过的坑（真实记录）

- **make_thumb 顺序 bug**：发布脚本里先生成缩略图、后清空旧归档，结果缩略图被自己清掉，首页裂图。这是本项目第一个真正意义的 bug，问题不在缩略图函数本身，在调用顺序。修了 3 行。
- **u2net 模型缓存**：抠图依赖 u2net 模型，沙箱环境缓存会丢，丢了就重新下载，一次几分钟。后来把模型缓存检查写进了预检脚本。
- **importmap 幂等**：前端模块映射是自动改写的，最初改写不是幂等的，跑两遍会重复加条目。改成"先查已存在就不加"之后，CI 里加了一项专门测它。
- **AI 生成失败恢复**：生图失败时如果直接中断，前面几层白生成。改成失败恢复：跳过失败的层重新生成，不重跑全部。

## 一个判断

四层方案的自由度很高（每层单独调），代价是生成成本是单图的四倍。批量做卡时，我优先保证四层风格一致，而不是每层都追求单图质量——一致性崩了，整批就废了。

分层是对的，但要用批量和 CI 把它约束住，不然自由会变成混乱。
