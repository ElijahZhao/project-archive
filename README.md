# project-archive

自用存档，收录**自己做过的各个项目**的开发过程与审查材料。

一句话分工：主仓库是展示面，回答"产品是什么 / 怎么用"；这里是过程面，回答"产品是怎么被做出来的"。

## 规矩

- **仅自用**：保持 Private，任何时刻不转 public。要给他人看时用 private invite。
- **不与主仓库关联**：不用 submodule / subtree；主仓库的文件、README、commit message、CI 里不出现本仓库名或链接。
- **不留 AI 痕迹类材料**：「AI 痕迹诊断」「去味方案」一类文件**不存档，直接删除**——这类文件本身就是最直接的痕迹证据，留档的风险大于留档的价值。
- **提交话术一律通用**：只写 `chore: update archive` / `docs: update` 这类，不写具体内容。
- 本仓库豁免敏感词扫描；主仓库若已推送公开，其历史不再改写，发现问题只往前处理、不回改历史。

## 目录

| 目录 | 放什么 |
| --- | --- |
| `01-过程证据/` | 调试日志、失败记录、废弃方案、历史处置记录——体现返工与艰辛的部分 |
| `02-审查产物/` | 文件体检报告、竣工度评审、修缮清单等审查结论 |

## 组织方式

按 `类型目录/项目名/` 存放，同一项目的材料落在对应的类型目录下。例如：

```
01-过程证据/cinerec/00-历史处置记录.md
02-审查产物/cinerec/01-文件体检报告.md
```

新项目按同样约定加入。
